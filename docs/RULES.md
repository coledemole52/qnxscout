# qnxscout rule reference

Generated by `qnxscout rules --markdown`. Every rule cites the public evidence it is based on.

| Severity | Meaning |
|---|---|
| `blocker` | will not compile or link on QNX 8.0 as written |
| `runtime` | builds, but is known to misbehave on QNX |
| `link` | needs a QNX library or a link flag, no code change |
| `review` | platform-dependent logic that needs a porting decision |
| `info` | background a porter should know |

## QNX001: epoll is not in QNX libc

**Severity:** `link` · **Category:** linux-api · **Typical effort:** trivial

QNX has no kernel epoll. QNX's own ports link a compatibility library instead (wayland, foot and python3 link -lepoll).

**Fix:** Link the QNX epoll compatibility library (-lepoll, github.com/qnx-ports/epoll). For simple loops poll() is enough; the native QNX model is ionotify() with pulses.

**Detects:** `epoll_create()`, `epoll_create1()`, `epoll_ctl()`, `epoll_wait()`, `epoll_pwait()`, `epoll_pwait2()`, `<sys/epoll.h>`

**Evidence:**

- [QNX agent skills: qnx-platform-facts](https://github.com/qnx/qnx-agent-skills/blob/main/skills/qnx-platform-facts/SKILL.md)
- [QNX compatibility library: qnx-ports/epoll](https://github.com/qnx-ports/epoll)
- [QNX port recipe (wayland)](https://github.com/qnx-ports/aports/blob/main/extra/wayland/APKBUILD)
- [QNX port recipe (foot)](https://github.com/qnx-ports/aports/blob/main/extra/foot/APKBUILD)

## QNX002: eventfd is not in QNX libc

**Severity:** `link` · **Category:** linux-api · **Typical effort:** trivial

eventfd() is a Linux kernel object; QNX's microkernel has no equivalent. The QNX Porting Guide recommends a shim, and QNX ships one (-leventfd, used by the wayland, foot and python3 ports).

**Fix:** Link -leventfd, or replace with a pipe()/socketpair() pair for wake-ups.

**Detects:** `eventfd()`, `eventfd_read()`, `eventfd_write()`, `<sys/eventfd.h>`

**Evidence:**

- [QNX Porting Guide (shim)](https://www.qnx.com/developers/docs/qnxeverywhere/com.qnx.doc.qpg/topic/sysarch_Create_shim.html)
- [QNX agent skills: qnx-platform-facts](https://github.com/qnx/qnx-agent-skills/blob/main/skills/qnx-platform-facts/SKILL.md)

## QNX005: inotify lives in libfsnotify, not libc

**Severity:** `link` · **Category:** linux-api · **Typical effort:** trivial

QNX 8.0 does implement inotify_init()/inotify_add_watch(), but in libfsnotify. Code that builds fine fails at link time with undefined inotify_* symbols.

**Fix:** Add -lfsnotify to the link line (and make configure checks link it).

**Detects:** `inotify_init()`, `inotify_init1()`, `inotify_add_watch()`, `inotify_rm_watch()`

## QNX007: System V shared memory needs the QNX shim

**Severity:** `link` · **Category:** linux-api · **Typical effort:** small

shmget()/shmat()/shmdt()/shmctl() are not in QNX libc. QNX publishes libsysv-ipc-shim (core/libsysv-ipc-shim) which implements them on POSIX shared memory.

**Fix:** Depend on libsysv-ipc-shim, or move to shm_open()+mmap() (native on QNX).

**Detects:** `shmget()`, `shmat()`, `shmdt()`, `shmctl()`, `<sys/shm.h>`

**Evidence:**

- [QNX compatibility library: qnx-ports/libsysv-ipc-shim](https://github.com/qnx-ports/libsysv-ipc-shim)

## QNX008: System V semaphores/message queues are not available

**Severity:** `blocker` · **Category:** linux-api · **Typical effort:** medium

semget()/semop()/msgget()/msgsnd() are absent from the QNX 8.0 C Library Reference, and QNX's SysV shim only covers shared memory.

**Fix:** Use POSIX semaphores (sem_open) and message queues (mq_open), or QNX message passing.

**Detects:** `semget()`, `semop()`, `semtimedop()`, `semctl()`, `msgget()`, `msgsnd()`, `msgrcv()`, `msgctl()`, `<sys/sem.h>`, `<sys/msg.h>`

**Evidence:**

## QNX011: getrandom()/getentropy() are not available

## QNX012: CPU affinity uses ThreadCtl() on QNX

**Severity:** `blocker` · **Category:** linux-api · **Typical effort:** small

sched_setaffinity()/pthread_setaffinity_np()/cpu_set_t are Linux interfaces (the onnxruntime port had to drop them). QNX sets affinity with run masks.

**Fix:** Use ThreadCtl(_NTO_TCTL_RUNMASK, ...) or _NTO_TCTL_RUNMASK_GET_AND_SET_INHERIT for the calling thread.

**Detects:** `sched_setaffinity()`, `sched_getaffinity()`, `pthread_setaffinity_np()`, `pthread_getaffinity_np()`, `pthread_attr_setaffinity_np()`, `sched_getcpu()`, `cpu_set_t`, `CPU_SET`, `CPU_ZERO`, `CPU_ISSET`, `CPU_COUNT`

**Evidence:**

- [QNX 8.0 C Library Reference: ThreadCtl()](https://www.qnx.com/developers/docs/8.0/com.qnx.doc.neutrino.lib_ref/topic/t/threadctl.html)
- [QNX port patch (onnxruntime): 0001-add-qnx-build.patch](https://github.com/qnx-ports/aports/blob/main/extra/onnxruntime/0001-add-qnx-build.patch)

## QNX014: Raw Linux syscalls are not available

**Severity:** `blocker` · **Category:** linux-api · **Typical effort:** small

## QNX017: sysconf(_SC_PHYS_PAGES) returns -1 on QNX

**Severity:** `runtime` · **Category:** runtime · **Typical effort:** small

QNX engineers confirmed sysconf(_SC_PHYS_PAGES) returns -1 on QNX 8.0, so memory-sizing code silently gets a negative or zero total (llama.cpp and WebKit needed QNX paths).

**Fix:** Read total memory from /proc/vm/stats or the memory manager (see the WebKit port); treat -1 as unknown.

**Detects:** `_SC_PHYS_PAGES`, `_SC_AVPHYS_PAGES`

**Evidence:**

## QNX026: Linux mcontext register layout does not apply

**Severity:** `blocker` · **Category:** linux-api · **Typical effort:** small

Code that reads uc_mcontext.gregs[REG_RIP] (crash handlers, profilers, GC) uses the Linux layout. QNX's mcontext_t is different (abseil and WebKit needed QNX code paths).

**Fix:** Add a __QNX__ branch reading the QNX register context (see the WebKit/abseil patches).

## QNX077: Architecture detection via CMAKE_SYSTEM_PROCESSOR

## QNX080: Sockets live in libsocket

**Severity:** `link` · **Category:** build · **Typical effort:** trivial

QNX keeps the BSD socket API in libsocket, not libc. The code uses sockets but the build does not link socket explicitly, so linking can fail with undefined socket()/connect()/getaddrinfo().
